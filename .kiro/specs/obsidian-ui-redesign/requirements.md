## Introduction

This feature is the ground-up redesign of the CompSaver CEP panel frontend for Adobe After Effects, modeled on MNTools v1.0.7 (the "Obsidian" studio look). It executes `REDESIGN-MASTER-PROMPT.md` (v4.0): a modular shell, an Obsidian design-token system, a persistent icon sidebar, a header with a live composition monitor, a 4-tab Toolkit Workbench that houses the Top-10 backlog features from `features/README.md`, a universal toast feedback engine, responsive dock breakpoints, a Ctrl/Cmd+K Command Palette, and a One-Framers FX browser.

The redesign is built on an existing, heavily tested codebase. Findings from inspecting it that shape these requirements:

- `index.html` is 1,764 lines. It links `css/tokens.css`, `settings.css`, `sidebar.css`, `components.css`, `command-palette.css`, `media-engine.css` and `style.css`. `style.css` imports 11 modules in a fixed order that `tests/class-contract.test.js` asserts.
- Modules the master prompt names already exist in part: `css/tokens.css`, `css/layout.css`, `css/components.css`, `css/toolkit.css`, `js/ui/header.js`, `js/ui/toast.js`, `js/ui/command-palette.js`, `js/ui/comp-monitor.js`, `js/ui/shell-state.js`. `css/toast.css`, `css/modals.css`, `js/ui/sidebar.js` and `js/ui/toolkit-workbench.js` do not exist yet.
- `js/ui/shell-state.js` defines exactly seven routes: `templates`, `tools`, `effects`, `text`, `easing`, `colorflow`, `settings`. The current sidebar has no Colors (ColorFlow) entry.
- Toolkit actions run through `runToolkitAction` (`js/toolkit/toolkit.js`) and `ToolBridge.call`. Current actions: `anchor`, `align`, `create`, `organize`, `effects`, `precompose`, `unprecompose`, `decompose`, `multiprecomp`, `truedup`, `sequence`, `resize`, `bounce`, `cache`, `guides-on`, `guides-off`, `delete-expression`, `paste`, `effect-save`, `effect-apply`, `effect-favorite`, `effect-rename`, `effect-delete`. Host implementations live in `jsx/toolkit.jsx`, `jsx/workflow.jsx`, `jsx/text.jsx` and `jsx/compSaver.jsx`.
- No host functions exist yet for FEAT-01 through FEAT-10 or FEAT-29.
- The Jest suite (`npm test`, jest 29.7.0 plus fast-check 3.22.0) has 130 suites and 1,587 tests. Before this work, 5 suites and 9 tests fail. The failing suites are `performance/contract-baseline`, `media-card-lifecycle-exploration`, `catalog-patch-ordering-exploration`, `media-card-lifecycle-preservation.property` and `metadata-cache-currency`. They belong to other open specs.
- Twelve test files read `index.html` as their static DOM source, and `tests/helpers/generate-baseline.js` and the `performance/contract-baseline` hash pins also depend on it. `tests/fixtures/class-contract.baseline.json` records 106 interactive ids, 104 JS-referenced static ids, 31 JS-resolvable classes and 8 JS-resolvable data attributes that must survive.
- `presets/oneframers_106_recipes.json` holds recipe objects of the form `{ name, color:[r,g,b], effects:[{ mn: string | string[], p: [[index, value], ...] }] }`. Some recipes reference third-party effects, with fallback match names.
- `js/ui/toast.js` currently uses `TOAST_DURATION` 3000 ms, hard-coded inline rgba colors, no `warning` type and no role/aria attributes. This feature changes the duration to 2000 ms (inside the 2000–4000 ms range `tests/toast.test.js` asserts) and moves toast colors to Design_Tokens.
- `guides-on` and `guides-off` (`toolkitAddGuides` / `toolkitClearGuides` in `jsx/workflow.jsx`) add and clear ruler guides at the edges and center of each selected layer's bounds. They are not rule-of-thirds guides.

## Glossary

- **Panel**: The CompSaver CEP extension UI running in After Effects' embedded Chromium (CEP, Chromium 88+).
- **Panel_Session**: The period from the Panel loading until it is closed or reloaded.
- **Host**: The ExtendScript side of CompSaver in `jsx/*.jsx`, executed by After Effects.
- **Shell**: The `index.html` document: the structural skeleton that holds the Header, Sidebar, view containers, toast surface and overlays.
- **View_Fragment**: A markup file outside `index.html` that holds the static markup of one route view (for example Templates, Flow or Text Animation) and is injected into the Shell at startup.
- **Composed_Markup**: The Shell markup with every View_Fragment inserted at its mount point. This is the DOM the Panel renders.
- **Bridge**: The CEP-to-Host transport made up of `encodeBridge`, `decodeBridge`, `decodeBridgeStrict`, `isWellFormedBridgeHex` and `callHost` in `js/core/bridge.js`, plus the matching host-side codec in `jsx/compSaver.jsx` and `jsx/core.jsx`.
- **Bridge_Payload**: A string encoded as 4 hex digits per UTF-16 code unit by `encodeBridge`.
- **Tool_Bridge**: The `ToolBridge.call` wrapper in `js/core/toolBridge.js`, used for all toolkit host calls.
- **Toolkit_Dispatcher**: The `runToolkitAction(action, mode, btn, event)` function that maps a toolkit action to a Host call.
- **Existing_Capability**: Any user-facing function that works in the Panel before this redesign. This includes Anchor Point, Align, Create Layer (Null, Parent Null, Adjustment, Camera, Solid, Text), Precompose, Multi-Precompose, Un-precompose, De-compose, True Duplicate, Crop Precomp, Sequence/Stagger, Resize Comp Tree, Bounce, Organize Project, Toggle Effects, Purge Cache, Guides On/Off, Remove Expressions, Paste Image, Effect Presets (save, apply, favorite, rename, delete), ColorFlow, Flow Curves, Text Animations, Templates (save, import, rename, move, delete, bulk delete, favorites, virtual grid) and Settings (including the accent picker).
- **Design_Tokens**: The CSS custom properties with prefix `--cs-` declared in `css/tokens.css`.
- **Legacy_Tokens**: The CSS custom properties declared in the `:root` of `css/base.css` and protected by `tests/token-foundation.test.js` and `tests/token-stability.test.js`.
- **Sidebar**: The persistent vertical navigation strip on the left of the Panel.
- **Route**: One of the seven Shell_State routes: `templates`, `tools`, `effects`, `text`, `easing`, `colorflow`, `settings`.
- **Shell_State**: The route controller in `js/ui/shell-state.js` that owns the active Route, performs Route navigation and keeps per-Route local state such as the `subsection` field.
- **Panel_Lifecycle**: The startup state machine in `js/core/appLifecycle.js`, with states that include `SHELL_VISIBLE`, `FIRST_CARD_USABLE`, `LIBRARY_READY` and `DEGRADED`. The template cold scan is the first scan of the template library after the Panel opens, which runs one section at a time.
- **Host_Call_Gate**: The startup gate that opens at the earliest of the lifecycle state `FIRST_CARD_USABLE`, the template cold scan completing with zero templates, or the lifecycle state `DEGRADED`. Automatic Host calls (Comp_Monitor queries and Workbench state probes) wait for it; Host calls the user starts do not.
- **Header**: The top bar of the Panel with the wordmark, the Comp_Monitor and the utility icons.
- **Comp_Monitor**: The Header pill that shows the active composition as `Name · WxH @ FPSfps`.
- **Workbench**: The Toolkit view (route `tools`) organized into four Workbench_Tabs.
- **Workbench_Tab**: One of `Layout & Rig`, `Velocity`, `Text`, `Guides`.
- **Toast_Engine**: The `js/ui/toast.js` module that shows feedback toasts through `showToast(msg, type)`.
- **Toast_Duration**: The time a toast stays visible before its exit transition starts.
- **Command_Palette**: The spotlight search overlay opened with Ctrl+K (Windows) or Cmd+K (macOS).
- **Palette_Entry**: One searchable, runnable item in the Command_Palette. Each entry has an id, title, category and run action.
- **OneFramer_Recipe**: One object in `presets/oneframers_106_recipes.json`.
- **Recipe_Parser**: The Panel component that reads the One-Framers JSON file into validated OneFramer_Recipe objects.
- **Recipe_Printer**: The Panel component that serializes OneFramer_Recipe objects back to the JSON recipe format.
- **FX_Browser**: The Effects-route grid that lists OneFramer_Recipes and applies them to the selected layers or, with Shift held, to a new adjustment layer.
- **Dock_Width**: The current inner width of the Panel in CSS pixels.
- **Narrow_Mode**: The layout used when Dock_Width is below 280px.
- **Standard_Mode**: The layout used when Dock_Width is from 280px to 550px inclusive.
- **Wide_Mode**: The layout used when Dock_Width is above 550px.
- **Card_Grid**: Any grid built on the `repeat(auto-fill, minmax(var(--grid-min-col), var(--grid-col-max)))` formula, such as the Templates grid and the FX_Browser grid.
- **Reference_Screenshots**: The 60 MNTools UI captures in `C:\Users\luvch\Downloads\reffrence tool for design\`.
- **MNTools_Reference**: The installed MNTools extension at `C:\Users\luvch\AppData\Roaming\Adobe\CEP\extensions\MNTOOLS\`, in particular `client/style.css`, `client/tools.html`, `client/kit.html` and `client/tool-data.js`.
- **Test_Baseline**: The Jest result recorded before this work: 5 failed suites and 9 failed tests, as listed in the Introduction.
- **Contract_Tests**: The static-analysis tests that read `index.html`, the CSS files or the JS files to assert DOM, class, id, data-attribute, import-order and script-manifest contracts. These include `class-contract`, `header-contract`, `toolkit-contract`, `templates-contract`, `panel-script-manifest`, `component-invariants`, `textanim-layout`, `cep-compat`, `token-foundation`, `token-stability` and `responsive-grid`.
- **Guide_Layer**: A Host-created layer marked as a guide layer, so After Effects does not render it.
- **Maintainer**: The CompSaver developer who runs the automated tests and the in-host verification for this feature.
- **Milestone**: One of the eight phases in REDESIGN-MASTER-PROMPT.md section 8 (Milestone 1 Tokens & CSS Framework, Milestone 2 Shell & Sidebar, Milestone 3 Toast Engine, Milestone 4 Workbench, Milestone 5 Top Features, Milestone 6 One-Framers FX Browser, Milestone 7 Command Palette, Milestone 8 Verification in After Effects). Each Milestone maps to one or more top-level tasks in the implementation plan.

## Requirements

### Requirement 1: Preserve Existing Capabilities

**User Story:** As a motion designer who relies on CompSaver every day, I want every tool I use today to keep working after the redesign, so that the new UI costs me no functionality.

#### Acceptance Criteria

1. THE Panel SHALL expose every Existing_Capability through at least one enabled, visible control that can be reached from the Panel's default startup state within at most 3 pointer clicks (the Sidebar Route click plus at most 2 further clicks, such as a Workbench_Tab or section toggle) in each of Narrow_Mode, Standard_Mode and Wide_Mode.
2. THE Toolkit_Dispatcher SHALL keep every existing action key (`anchor`, `align`, `create`, `organize`, `effects`, `precompose`, `unprecompose`, `decompose`, `multiprecomp`, `truedup`, `sequence`, `resize`, `bounce`, `cache`, `guides-on`, `guides-off`, `delete-expression`, `paste`, `effect-save`, `effect-apply`, `effect-favorite`, `effect-rename`, `effect-delete`) mapped to the same target it used before the redesign: the same Host function call issued through Tool_Bridge with the call key `toolkit.<action>` for Host-bound actions, and the same Panel-side handler for `paste` and the five `effect-*` actions.
3. WHEN a redesigned control triggers an Existing_Capability with a given action key, mode string and modifier-key state, THE Panel SHALL send the same Host function name and a byte-identical Bridge_Payload argument string to the ones the pre-redesign control sent for that same action key, mode string and modifier-key state.
4. WHEN the user clicks the Null create control and the click event reports that the Shift key is not held, THE Toolkit_Dispatcher SHALL call `toolkitCreateParentNull()` exactly once and SHALL NOT call `toolkitCreateLayer`.
5. IF the Null create action is triggered with the Shift key held, or is triggered without a pointer event (for example from a Palette_Entry), THEN THE Toolkit_Dispatcher SHALL call `toolkitCreateLayer` exactly once with the Bridge_Payload encoding of the mode `null`, matching the pre-redesign behavior.
6. WHEN the Panel finishes startup, THE Panel SHALL have the ColorFlow, Flow Curves, Text Animation, Effects Presets, Templates and Settings controllers (`colorflow.js`, `flow.js`, `textanim.js`, `effects.js`, `templates.js`, `settings-panel.js`) initialized against the Composed_Markup without throwing an uncaught error, and every interactive id, JS-referenced static id, JS-resolvable class and JS-resolvable data attribute recorded in `tests/fixtures/class-contract.baseline.json` SHALL be present in the Composed_Markup.
7. THE Panel SHALL keep the public function names, argument lists, return values and side effects of every file in `js/core/` unchanged; the only permitted edits to `js/core/` files are additions of new registry entries (such as capability or bridge registry entries) that leave existing entries and existing code lines unmodified.
8. WHEN a Host-bound toolkit action completes with a success result, THE Panel SHALL show feedback as Requirement 14.10 and 14.11 define.
9. WHERE the `Quiet rapid tools` setting is enabled, WHEN `anchor`, `align`, `sequence`, `guides-on`, `guides-off` or `delete-expression` completes with a plain success result, THE Panel SHALL show no toast, matching the pre-redesign behavior.
10. IF a toolkit action's pre-redesign input validation fails (for example no resolution or a frame rate of 0 or less selected for `resize`), THEN THE Panel SHALL show an error toast indicating the missing or invalid input, SHALL NOT issue any Host call for that action, and SHALL leave the entered control values unchanged.
11. WHEN the Jest suite is run with `npm test` after the redesign, THE Panel codebase SHALL pass every Contract_Test, and the set of failing suites and tests SHALL be a subset of the Test_Baseline's 5 failed suites and 9 failed tests.

### Requirement 2: Bridge Contract and Host Script Constraints

**User Story:** As the maintainer of CompSaver, I want the CEP-to-Host contract and the ExtendScript language rules kept intact, so that no host call breaks inside After Effects.

#### Acceptance Criteria

1. THE Bridge SHALL keep the parameter lists, return types and encoding behavior of the following functions identical to their pre-redesign versions in `js/core/bridge.js` and the matching host-side codec in `jsx/compSaver.jsx` and `jsx/core.jsx`: `encodeBridge(str)` returns a string of 4 lowercase hex digits per UTF-16 code unit, and returns an empty string for `null`, `undefined` or `""`; `decodeBridge(hex)` returns a string; `decodeBridgeStrict(hex)` returns an object with an `ok` boolean, a `value` string and, when `ok` is false, an `error` string; `isWellFormedBridgeHex(hex)` returns a boolean; `callHost(scriptCall, options)` returns a Promise that never rejects, resolves with an `ok` boolean plus one of `result`, `error` or `timedOut`, and uses a default timeout of 30,000 ms.
2. FOR ALL strings s of 0 to 10,000 UTF-16 code units, including the empty string, control characters, quote and backslash characters, and non-BMP characters encoded as surrogate pairs, THE Bridge SHALL satisfy `decodeBridge(encodeBridge(s)) === s` and `encodeBridge(s).length === 4 × s.length` (round-trip property).
3. WHEN the Panel sends a user-supplied string to the Host (a layer name, find/replace text, preset name, recipe payload, or any other text from a Panel input field, preset file or recipe file), THE Panel SHALL pass that string only as a Bridge_Payload argument, with no raw user text interpolated into the ExtendScript expression given to `callHost`, `ToolBridge.call` or `evalScript`.
4. THE Host code in every `jsx/*.jsx` file SHALL use only ECMAScript 3 syntax: `var` declarations and `function` declarations or expressions, with no `const`, `let`, arrow functions, template literals, classes, destructuring, spread, rest parameters, default parameters, `for...of` loops or getter/setter literals.
5. WHEN a Host function added or modified by this feature changes a layer, property, keyframe, composition or project item, THE Host SHALL wrap all of those changes in one invocation between exactly one `app.beginUndoGroup(<action name>)` and one matching `app.endUndoGroup()`, where `<action name>` is a non-empty string naming the action, and SHALL call `app.endUndoGroup()` on every return path after `app.beginUndoGroup`, early-return validation paths included.
6. IF a Host function added or modified by this feature throws after `app.beginUndoGroup` has been called, THEN THE Host SHALL catch the exception, call `app.endUndoGroup()` inside its own guard so a second failure cannot escape, and return an error result string (per criterion 7) that describes the failure, so that no uncaught exception reaches `evalScript`.
7. THE Host functions added by this feature SHALL return their result as a Bridge_Payload of a result string that follows the existing convention: `"true"` for silent success, a string that starts with `"OK:"` followed by a non-empty message for success with a message, and any other non-empty string (neither `"true"` nor starting with `"OK:"`) for an error that describes the failure cause, and SHALL never return `undefined`, an empty string or a value that is not Bridge_Payload encoded.
8. THE Panel frontend modules under `js/` SHALL use only ECMAScript syntax up to and including ES2020 that Chromium 88 parses without a transpiler, and SHALL contain no ES module `import` or `export` statements, so that each module loads as a classic `<script>` in the Panel.
9. THE Panel frontend modules under `js/` added or modified by this feature SHALL expose their public API as globals and end with the CommonJS dual-load guard `if (typeof module !== "undefined" && module.exports) { module.exports = { ... }; }`, so that Jest can `require` each module without a `window`, `csInterface` or DOM being present and without throwing at load time.
10. IF `decodeBridgeStrict` receives a non-empty input whose length is not a multiple of 4 or that contains a character outside `0-9`, `a-f` or `A-F`, THEN THE Bridge SHALL return `ok` false with an empty `value` and an `error` string that indicates a malformed payload, `decodeBridge` SHALL return an empty string for the same input, and `callHost` SHALL resolve with `ok` false and that error instead of a decoded result.
11. WHEN a Host function added by this feature receives a Bridge_Payload that holds JSON text (for example a OneFramer_Recipe payload), THE Host SHALL decode it with the host-side `decodeBridge` and parse it with the strict `jsonParse` parser from `jsx/core.jsx`, SHALL NOT pass it to `eval` or any other code-executing construct, and SHALL return an error result string (per criterion 7) without changing the project if decoding or parsing fails.
12. THE Panel's CEP manifest (`CSXS/manifest.xml`) SHALL declare CSXS 11.0 as the minimum required CEP runtime, so that hosts with CEP 10 or older (Chromium below 88, After Effects versions before 2022) do not load the Panel.

THE Panel SHALL keep each of the 31 JS-resolvable classes and the 8 JS-resolvable data attributes in the class-contract baseline resolvable, where resolvable means the class or data attribute appears on at least one element of the Composed_Markup or in the selector of at least one CSS rule in a `css/*.css` file.

WHERE markup moves out of `index.html` into View_Fragments, THE shared static-analysis helper (`tests/helpers/static-analysis.js`) SHALL build the Composed_Markup by inserting each View_Fragment exactly once at its mount point in the Shell, and SHALL return the same Composed_Markup on every call for the same Shell and View_Fragment files.

13. THE feature SHALL add, for every new JS module, new Toolkit_Dispatcher action and new Host function it introduces, at least one Jest test that runs under `npm test`, exercises that module, action or function by name, and passes; for each new Toolkit_Dispatcher action and new Host function, the tests SHALL cover the success path and at least one failure path (for example, no active composition or no selected layers).

### Requirement 4: Modular Shell and File Decomposition

**User Story:** As the maintainer, I want the monolithic `index.html` split into a small shell plus focused modules, so that the panel is easier to change and quicker to parse.

#### Acceptance Criteria

1. THE Shell (`index.html`) SHALL contain at most 300 lines, counted as the number of newline-separated lines in the file on disk, including blank lines and comment lines.
2. THE Shell SHALL contain the Header, the Sidebar, exactly one mount container for each of the seven Routes, the toast surface, the Command_Palette overlay container and the ordered `<script>` manifest, and SHALL contain no static markup of a Route view inside any mount container.
3. THE Panel SHALL provide the stylesheets `css/tokens.css`, `css/layout.css`, `css/components.css`, `css/toolkit.css`, `css/toast.css` and `css/modals.css`, each loaded exactly once by the Composed_Markup through a `<link>` element or a `css/style.css` import, with `css/tokens.css` loaded before every other stylesheet.
4. THE Panel SHALL scope each new stylesheet to its named concern, such that `css/toast.css` contains only rules whose selectors target the toast surface or toast elements, and `css/modals.css` contains only rules whose selectors target modal dialogs, modal backdrops or overlay containers.
5. THE Panel SHALL provide the UI modules `js/ui/sidebar.js`, `js/ui/header.js`, `js/ui/toast.js`, `js/ui/command-palette.js` and `js/ui/toolkit-workbench.js`, each listed exactly once in the Shell's script manifest.
6. WHEN the Panel starts, THE Shell SHALL insert each View_Fragment exactly once into the mount container of its Route, and SHALL complete that insertion before any JS controller that binds to that fragment's elements runs its init function.
7. THE Shell SHALL keep `js/core/pathBuilders.js` listed exactly once and before `js/core/utils.js` in the script manifest.
8. THE Shell SHALL list `js/core/bridge.js`, `js/core/toolBridge.js` and `js/ui/toast.js` in the script manifest before any script that calls `encodeBridge`, `ToolBridge.call` or `showToast` during its top-level evaluation (code that runs when the script loads rather than inside a later function call).
9. THE Shell SHALL list each script file at most once in the script manifest, with no two `<script>` elements sharing the same `src` value.
10. IF a View_Fragment fails to load, meaning the file is missing, unreadable, empty, or not inserted within 5,000 ms of Panel start, THEN THE Shell SHALL call the Toast_Engine with type `error` once for that View_Fragment and a message that names the failed view.
11. IF a View_Fragment fails to load, THEN THE Shell SHALL leave that Route's mount container empty, SHALL skip the init function of every JS controller that binds only to that fragment's elements, and SHALL raise no uncaught exception.
12. IF a View_Fragment fails to load, THEN THE Panel SHALL keep every other Route working, so that selecting another Route in the Sidebar shows that Route's view and every Existing_Capability hosted in that Route stays runnable.

### Requirement 5: Obsidian Design Tokens

**User Story:** As a motion designer, I want a consistent dark obsidian look with my chosen accent color, so that the panel feels like one coherent, professional tool.

#### Acceptance Criteria

1. THE Design_Tokens SHALL declare on `:root` `color-scheme: dark` and every token listed in REDESIGN-MASTER-PROMPT.md section 2 (7 surface tokens, 4 border tokens, 4 text color tokens, 7 accent tokens, 6 semantic color tokens, 2 font stack tokens and 5 radius tokens).
2. WHILE `--cs-user-accent` is unset, THE Design_Tokens SHALL compute each token listed in REDESIGN-MASTER-PROMPT.md section 2 to the exact value given there.
3. THE Design_Tokens SHALL declare `--cs-accent` as `var(--cs-user-accent, var(--cs-accent-default))`, with `--cs-accent-default` equal to `#3b82f6`, so that `--cs-accent` computes to `#3b82f6` whenever the accent system has not set `--cs-user-accent`, for example before accent initialization or when Settings is unavailable.
4. WHEN the existing accent system (`js/ui/accent.js`) applies an accent color (any of the six presets, including the default `blue` preset `#4f8cff`, or a valid custom hex), THE Panel SHALL set `--cs-user-accent` on the document root to that color in lowercase `#rrggbb` form within 100 ms and without a Panel reload.
5. WHEN the Panel restarts, THE Panel SHALL read the `appearance.accent` and `appearance.accentCustom` values saved before the restart and set `--cs-user-accent` to the resolved color before the first Route view is displayed.
6. THE Panel SHALL keep unchanged the six accent presets and their colors (`blue` `#4f8cff`, `violet` `#9b7bff`, `teal` `#14b8a6`, `green` `#22c55e`, `amber` `#f59e0b`, `rose` `#f43f5e`), the setting defaults `appearance.accent` = `blue` and `appearance.accentCustom` = `#4f8cff`, and the Legacy_Tokens `--primary` family values, so that `accent-theme.test.js`, `accent-picker.test.js` and `token-stability.test.js` all pass.
7. THE stylesheets for the redesigned components (the Shell, Header, Comp_Monitor, Sidebar, Workbench, toast surface, Command_Palette and FX_Browser) SHALL specify colors, border radii and font families only through `var(--cs-…)` Design_Tokens, and SHALL contain no literal hex colors, no `rgb()`, `rgba()`, `hsl()` or `hsla()` color literals, no non-zero pixel `border-radius` values and no font family names; the keywords `transparent`, `currentColor`, `inherit` and `none`, and radius values `0` and `50%`, are exempt.
8. ### Requirement 14: Toast Feedback Engine

**User Story:** As a motion designer, I want clear feedback after every action, so that I never wonder whether a tool worked.

#### Acceptance Criteria

1. THE Toast_Engine SHALL display toasts horizontally centered at the bottom of the Panel, on a glass surface whose background, border and blur values come from Design_Tokens, with a width of at most Dock_Width minus 16px, long messages wrapping, and no horizontal overflow at any Dock_Width in Narrow_Mode, Standard_Mode or Wide_Mode.
2. THE Toast_Engine SHALL support the types `success`, `info`, `warning` and `error`, each with its own icon and its own semantic color taken from Design_Tokens, with no two types sharing an icon or a color.
3. IF `showToast` receives a type that is missing or not one of `success`, `info`, `warning` and `error`, THEN THE Toast_Engine SHALL render the toast as `info`.
4. WHEN a toast becomes visible, THE Toast_Engine SHALL keep it fully visible for a Toast_Duration of 2000 milliseconds, then run a fade-out exit transition of at most 300 milliseconds, and once the exit transition finishes SHALL show the next queued message, if one exists.
5. WHILE a toast is visible or running its exit transition, THE Toast_Engine SHALL queue new messages in FIFO order and hold at most 8 queued messages.
6. WHEN a ninth message arrives while 8 messages are queued, THE Toast_Engine SHALL drop the oldest queued message and keep the other 7 in their original order.
7. THE Toast_Engine SHALL show at most one toast at a time, and SHALL start a new toast only after the previous one's exit transition has finished.
8. WHEN a toast is displayed, THE Toast_Engine SHALL set the toast surface to `role="status"` with `aria-live="polite"` for `success` and `info`, and to `role="alert"` for `warning` and `error`, applying these attributes before the message text is inserted.
9. IF a Host call through Tool_Bridge times out (default 30000 milliseconds), returns no usable response, cannot be dispatched, or returns a Host error string that does not report a failed precondition as criterion 13 describes, THEN THE Panel SHALL show an `error` toast that states which of these four causes occurred, and SHALL restore the triggering control to the enabled or disabled state it had before the call.
10. WHEN a Host action succeeds, THE Panel SHALL show a `success` toast that names the completed action and, where the Host reports an affected item count, includes that count (for example `✓ 12 layers aligned to Comp Center`).
11. WHERE the user enables the `Quiet rapid tools` setting (disabled by default), THE Panel SHALL suppress only the `success` toasts for the `anchor`, `align`, `sequence`, `guides-on`, `guides-off` and `delete-expression` actions, SHALL show the result through the control's active state, and SHALL still show `warning` and `error` toasts for those actions.
12. IF `DOM.toast` is missing when `showToast` or `clearToast` is called, THEN THE Toast_Engine SHALL return without throwing and without changing the queue.
13. IF the Host reports, through a result string that the Panel can distinguish from other error strings, that an action could not run because a precondition was not met (for example, no active composition or no layers selected), THEN THE Panel SHALL show a `warning` toast that names the missing precondition, and SHALL leave the project unchanged.
14. IF Tool_Bridge rejects a call because the same action is already in progress, THEN THE Panel SHALL show an `info` toast saying the action is still running, at most one such toast per action key in any 1500-millisecond window, and none for callers that opt out of busy feedback.
15. WHEN `clearToast` is called, THE Toast_Engine SHALL hide the current toast immediately, cancel any pending dismiss or advance timers, and empty the queue, so no queued message appears afterward.
